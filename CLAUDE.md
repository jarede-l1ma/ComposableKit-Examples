# POC_TCA — ComposableKit (TCA-style architecture for SwiftUI, iOS 15+)

This project is the proof of concept of **ComposableKit**, a dependency-free implementation of Point-Free's TCA API. Talk to the user in Portuguese; the project itself (code, comments, docs, skill) is in English.

**Scope: 4 independent artifacts** — none depends on another (decided 10/10/2026):
- `ComposableKit` package: what apps depend on, like Point-Free's TCA. Verified by its own `swift test`.
- `composablekit-create.py`: creates scenes for the package (it knows the package's API, nothing else). It does **not** generate tests.
- `ios-tca-tests` skill: the developer runs it when the feature is done; it reads the scene's real code, writes the tests and the test target helpers, runs them until green. It does not depend on the script.
- The POC: a usage example of the package (`Home` → `HomeDetails`, plus `Sample` = raw script output, regenerated with `--force`). Verified by its own tests.
There is no cross-artifact validation script anymore (`validate.sh` was removed on purpose); docs: `README.md` (project overview), `docs/ARCHITECTURE.md` (architecture guide) + this CLAUDE.md.

## Architecture: ComposableKit (same API as Point-Free's TCA)

- `@Reducer struct XFeature` with `@ObservableState struct State: Equatable`, `enum Action: Equatable` and `var body: some ReducerOf<Self> { Reduce { state, action in ... } }`.
- The `@Reducer` macro applies `@CasePathable` to `Action`, `@ObservableState` to `State` and `@ReducerBuilder` to `body`.
- Effects: `.none`, `.send`, `.run { send in } catch: { error, send in }`, `.merge`, `.concatenate`, `.cancellable(id:cancelInFlight:)`, `.cancel(id:)`, `.debounce(id:for:clock:)`.
- Dependencies: `@Dependency(\.xClient)`; client = struct of `@Sendable` closures with `liveValue`/`testValue`. Built in: `continuousClock` (`EffectClock`, `TestClock`, `ImmediateClock`), `uuid`, `date`.
- Composition: `Scope`, `.ifLet`, `.forEach` (`IdentifiedArrayOf`, `IdentifiedActionOf`), `store.scope(state:action:)`.
- Forms: `BindableAction` + `BindingReducer()` + `$store.field`. Reducer modifiers: `.onChange(of:)`, `.dependency(_:_:)`, `._printChanges()`.
- Shared state: `@Shared(.inMemory / .appStorage / .fileStorage)`, mutated with `$field.withLock`.
- Store: `ObservableObject` (iOS 15+); the View uses `@ObservedObject var store: StoreOf<XFeature>`; redraws per screen (not per field).
- Tests: exhaustive `TestStore`, `TestClock`, `LockIsolated`. The test target needs `Helpers/ComposableKitTestSupport.swift` (class `ComposableKitTestSupport`, found by name through the ObjC runtime), otherwise TestStore failures do not fail the test.
- The app's test target does **not** link the package (only `import ComposableKit`), to avoid two copies of the library.

## Scene (5 files, generated by `python3 composablekit-create.py <Scene> POC_TCA/Scenes`)

- `Core/<Scene>Feature.swift` — State, Action, body, `CancelID`, `navigate` (injected closure), `analyticsEvent(for:state:)`, `enum <Scene>Route`.
- `UI/<Scene>View.swift` — View (native SwiftUI components) + `@MainActor enum <Scene>Factory { make(navigate:) }` returning `UIHostingController` + Preview.
- `Service/<Scene>Service.swift` — Response + `<Scene>Client` (dependency) + `nonisolated struct <Scene>Service` using `URLSession` async/await (cancelling the effect cancels the request). In the POC, Home/HomeDetails services read `OMDBFakeAPI`.
- `Service/<Scene>Mapper.swift`, `Service/<Scene>AnalyticsModel.swift` (events conform to `AnalyticsEvent`: `name` + `parameters`).
- Analytics: `AnalyticsClient` (`@Dependency(\.analytics)`) + `nonisolated protocol AnalyticsEvent`, defined once per module; the script creates `Shared/Analytics/AnalyticsClient.swift` next to the scenes folder when no file declares `var analytics: AnalyticsClient`.

## Commands

```bash
# Package: build + tests. The --scratch-path outside the Desktop avoids the codesign error
# "resource fork, Finder information, or similar detritus not allowed" (synced Desktop).
cd Packages/ComposableKit && swift build --build-tests --scratch-path /tmp/ck-build && swift test --scratch-path /tmp/ck-build

# POC: tests on the simulator
xcrun simctl list devices available | grep iPhone
xcodebuild test -project POC_TCA.xcodeproj -scheme POC_TCA \
  -destination 'platform=iOS Simulator,name=iPhone 17' -skipMacroValidation \
  -collect-test-diagnostics never -only-testing:POC_TCATests
# (-collect-test-diagnostics never: with a failing test, xcodebuild otherwise sits ~10 min in simctl diagnose)

# New scene (tests come later, from /ios-tca-tests <Scene>)
python3 composablekit-create.py SceneName POC_TCA/Scenes

# After changing the scene template: generate a throwaway scene in the POC, build/test the POC
# (also with SWIFT_VERSION=6), then remove the scene.

# Update swift-syntax (build-only macro dependency) in the package and in the POC
cd Packages/ComposableKit && swift package update swift-syntax
# POC: Xcode › File › Packages › Update to Latest Package Versions (or xcodebuild -resolvePackageDependencies)

# Slow CI: raise the TestStore timeout (default 1 s)
TEST_RUNNER_COMPOSABLEKIT_TEST_TIMEOUT=5 xcodebuild test ...   # swift test: COMPOSABLEKIT_TEST_TIMEOUT=5
```

Run the build/tests after any change and only say something works after seeing it pass.

## Current state (10/10/2026)

- Generalized from a company-specific project (10/10/2026): package renamed to `ComposableKit` (clock protocol → `EffectClock`, test support class → `ComposableKitTestSupport`, env var → `COMPOSABLEKIT_TEST_TIMEOUT`), script → `composablekit-create.py`, design-system components → native SwiftUI, custom networking → `URLSession`, company analytics protocol → generic `AnalyticsEvent`; everything translated to English. Domain example scenes were removed (kept: `Home`, `HomeDetails`, `Sample`). Backup of the previous state: `~/Documents/Projects/backups/pre-composablekit-2026-10-10.tar.gz`; moved-out files in `~/Documents/Projects/backups/removed-2026-10-10/`.
- Package green (179 tests + 6 macro tests, no warnings, Swift 6). POC green in Swift 5 (`xcodebuild test`, no warnings). The scene template was verified (10/10/2026) in Swift 5 and Swift 6, and in an iOS 15 package with and without default `MainActor` isolation.
- `Reducer` follows TCA's design: `_reduce` requirement + `associatedtype Body` without a default; `ReducerOf<R: _ReducerTypes>` (not `R: Reducer`) to avoid "circular reference" when the feature is used from another file. `@Reducer` generates `extension X: Reducer, _ReducerTypes {}` (both explicit) so the witness table is always emitted.
- With default `MainActor` isolation: `CancelID` must be a `nonisolated enum`, and `navigate` must be `nonisolated var navigate: @MainActor @Sendable (Route) -> Void` (otherwise the closure loses `@MainActor` when captured in `.run` → crash creating the next Store). Regression test: `navigateShouldRunOnMainThread`. `Response`, `Service`, `ViewData` and fixtures are `nonisolated`.
- `TestStore.receive` waits up to ~50 ms for effects to settle (`settleEffects`); `TestClock.advance` waits for a late `sleep` to register (regression `advanceWaitsForASleepThatRegistersLate`). Timeouts scale with `COMPOSABLEKIT_TEST_TIMEOUT`.
- Cancellation ids are namespaced per child (`.forEach` per element, `.ifLet` per destination); `Scope` shares the parent's namespace (as in TCA).
- `@Shared`: one registry per test (via `currentTestScope`), `.appStorage` in memory in tests unless `defaultAppStorage` is set, only Stores containing the changed value are notified, `.fileStorage` writes on a serial queue and flushes on background/termination.
- Concurrency: no `nonisolated(unsafe)`; every `@unchecked Sendable` has its invariant commented; Thread Sanitizer: 0 data races.
- Script: existing scene → only missing files are created; `--force` resets to the template; creates `Shared/Analytics/AnalyticsClient.swift` when the module has none.
- swift-syntax (build only, macros): range `600.0.0..<700.0.0`, pinned to the latest stable in both `Package.resolved` files (package and `POC_TCA.xcodeproj/project.xcworkspace/xcshareddata/swiftpm`), today 604.0.0 (keep both in sync).

## Known limitations

See docs/ARCHITECTURE.md §14 ("Known limitations and choices to make"). Without default isolation, the Coordinator/router that calls the Factories must be `@MainActor` (the POC's `AppRouter` is not, so the whole POC does not compile without default isolation).
